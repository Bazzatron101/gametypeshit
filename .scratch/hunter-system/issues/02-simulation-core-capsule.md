# 02: Simulation core with a movable capsule

**What to build:** A fixed-timestep simulation that takes per-player input commands and produces state, with a capsule moving on a greybox floor in the game, and the same movement reproduced by a headless test. Player state is addressable per player from the start (no singleton player), so single-player is the one-player case of the multiplayer model.

**Blocked by:** 01: Project scaffold

**Status:** ready-for-agent

- [x] Simulation runs on a fixed timestep independent of rendering and the engine's scene objects
- [x] Player input is expressed as commands per tick and the capsule moves in the game as a result
- [x] A headless test feeds scripted commands and asserts the resulting position
- [x] Player state is keyed per player, with no global player singleton

## Comments

**2026-11-11 (agent):** Implemented.
- Core: `Assets/Scripts/Simulation/` is a pure C# assembly with no engine references (`noEngineReferences: true`). `SimulationWorld.Step(commands)` advances one fixed tick from a `PlayerId` to `PlayerCommand` map. `FixedTimestepClock` turns frame time into whole ticks.
- Game: `SimulationRunner` drives the world from Unity and `PlayerView` draws the capsule, interpolated between ticks. The local player reads the project-wide `Player/Move` action (WASD, arrows, left stick). Movement is world-relative until ticket 05.
- Scene: `Assets/Scenes/Greybox.unity`, generated by `Hunter System > Rebuild Greybox Scene` (`Assets/Editor/GreyboxSceneBuilder.cs`), and now the first build scene.
- Tests: headless movement in `SimulationMovementTest` and the clock in `FixedTimestepClockTest`. `GreyboxCapsuleTest` (PlayMode) checks that the capsule moves in the real scene.

Deferred review findings, for later tickets:
- **03/04 (attack, dodge):** input is sampled once per frame. A press shorter than one tick (about 16 ms) on a frame that runs 0 ticks is lost, and frames that run several ticks repeat the command. Button presses need latching until consumed by a tick.
- **03:** the spec says the simulation "produces state and events". There is no event output yet; damage events arrive with ticket 03.
- **12 (netcode spike):** commands carry no tick number. Prediction and reconciliation will need tick-stamped commands. Positions are floats, deterministic on one machine but not guaranteed across machines, which is acceptable under host authority.
